# 十方向职业探索 V2.0：实现与验收

本次基于用户提供的《AI Career Navigator 十方向职业探索题库 V2.0》升级现有原生 JavaScript 应用。没有改写题库，没有新建网站，没有部署或调用 GPU。

## 原始内容与完整性

项目根目录原始交付包包含完整 JSON、前端 JSON、评分映射、完整审阅 Markdown、质检摘要、使用说明及 Excel。完整阅读了 84 道题及解释规则，并逐项验证完整 JSON / 前端 JSON / 评分映射 / Markdown 的题干、选项、标签、阶段和解释一致。

运行文件 `prototype/exploration/bank.json`、`scoring.json` 是用户提供对应文件的逐字节副本。`source-manifest.json` 保存原始文本文件的 SHA-256。测试对照原件，而非另造一份预期题库；原始 Excel 保留未修改，开发优先使用 JSON。

十方向：SW、DATA、FIN、PM、MKT、DES、ENG、HLT、EDU、OPS。每个方向载入 G01–G04 与该方向 01–08；题库共 84 题，每次显示 12 题。

题库没有多选类型配置，各题采用符合“最想／最接近／更愿意”的单选。五／六个选项是原题的不同情境与经历描述，**不是统一熟练度等级控件**。所有 U 原文保留。源文件各题 `required: false`，因此允许跳过，不强迫猜测；跳过与 U 均显示资料不足，和阶段 0 明确区分。

## 用户流程

入口选一个方向 → 简短虚构情境说明 → 点击“使用虚构情境开始” → 六屏、每屏两题 → 本地报告。

- 无姓名、简历、上传或自由输入框；不再要求原来的专业／任务／熟练程度附加题。
- 可上一步、修改选项、切换方向、重新开始；切换方向保留 G01–G04，清除旧方向答案，防止串题。
- 两份现有虚构案例改用 MKT / OPS 的原题选项，明确为演示预填，可修改。V0.1 脚本演示仍保留在原有独立入口。
- 比赛审查记录要求公开／开放／虚构资料；本流程保留一次入口说明及明确开始按钮，不添加重复勾选或弹窗。只有主动请求可选 AI 时才另行确认外部分享。

## 确定性解释规则

`profile.exploration = {version, direction, answers: {questionId: optionId}}` → `analyzeExploration` → `buildExplorationReport` → 既有报告导航。

- G01、G02、G03 与方向 01、03、04、07、08：保留原始 tag，只作动机、目标、时间和任务偏好解释，不评分。
- 方向 02：0–4 的**自述经历阶段**；0 表示尚未尝试，不是低潜力。
- G04 与方向 05：分别展示通用／方向 AI 接触阶段 0–4，不求和、不平均、不换算能力分。
- 方向 06：保留题库各选项的 0–3 策略级别及原情境文本，不出现“答对／答错”，不声称观察到实际操作能力。
- U 或跳过：null / unknown，不当 0。关键经历、通用 AI、方向 AI 或核查信息缺失时明确提示。
- 不根据一题推断人格或职业资格，不对未回答的其他方向排序，不生成 V2 职业适合度百分比。
- 成长取舍反映选择的挑战；没有直接询问的 AI 学习意愿不作强行推断。建议先自愿尝试可核查的小步骤。

## 报告与既有功能

保留能力／AI 与工作／职业路径／行动计划，以及星图、比较路线、技能 DNA、未来情景、SDG 关联的原有导航与交互。V2 使用独立报告数据适配层；旧版报告、旧规则评分函数与 RunPod 后端不重写。

V2 的两个路线是**已选择方向内的兴趣导向／任务导向体验**，不是宣称用户适合两个不同职业。报告显示：兴趣与细分领域、处理困难的偏好、自述经历、通用与方向 AI 使用、核查策略、成长挑战、具体实践与资料边界。所有原始选择可展开核对。

十方向各有一项团队编写、无需专业背景的微项目建议（不是新题目）：例如纸面软件原型、虚构数据图表、虚构预算、校园工具验证计划、传播小样、校园指引、节能装置纸面方案、健康信息来源笔记、概念讲解卡、活动交接流程。它们明确为编辑建议，不冒充官方职业准入要求。

计划依据原经历阶段提供观察／跟随示例／调整模板／独立样本等支架，依据 G02 调整探索、比较、下一步或 AI 变化的行动重点。兴趣与任务选项作为明确的练习聚焦内容显示。每份计划包括准备、制作、核查三段、交付物、错误记录和官方参考。低时间预算先在第一周体验一部分，完整练习可跨周继续；不承诺短时间取得资格。

## What If

V2 保留同一网站里的即时模拟入口，并按原题库边界调整控件：

- 每周实践时间 0.5–20 小时：只重新排期。
- 假设经历：使用该方向原第 02 题选项，显示原阶段 → 假设阶段、练习支架变化和工时估计；不写回原答案。
- 假设经历为 U 时保持未知。AI 接触与核查阶段不随模拟变化。
- G03 时间区间转换为明确的排期示例：<1h 用 0.5，1–3 用 2，3–6 用 4，>6 用 7。不是用户精确报告的工时；未知时先用 1h 示例并明确标注。
- 示例任务工时由练习支架确定，属于团队估算，不是官方资格门槛或技能提升预测。
- `simulateExploration` 是纯本地函数；不请求 AI、不查询外部数据。旧版报告的既有模拟器与评分逻辑继续保留。

## 三语言与可选 AI

方向名称使用原交付包已有的中英马名称。题干、选项、解释和原答案引用保持中文，放在有 `lang="zh-CN"` 标记的独立内容块，避免全局翻译器改写原文。英文／马来文界面明确提示题目待翻译；导航、结果解释和模拟控件仍使用对应语言。没有自行批量翻译 84 道题。

普通提交、语言切换、报告查看及模拟不请求生成式 AI。既有 RunPod 配置、API Key 后端保护、额度、超时与重复请求保护未修改。

主动选择 AI 时，适配器去除新增前端字段，将十二项真实选项、标签和阶段以紧凑上下文传给现有严格后端。未采集的技能／顾虑明确标为未测量，不编造专业经历；练习明确标为建议练习而非已做工作。旧 API 最小时间为 1h，仅可选请求按旧契约适配，不改变本地 0.5h 排期。可选 AI 只单独显示文字解读，不展示其旧格式的其他职业排名，不替换本地分类。失败时保留完整基础报告。
